# Stage Gateway v2 separation candidate

The CPU workbench keeps its current native path unless `STUDIO_GATEWAY_V2_SEPARATION=1`. The switch applies only to Duality v2, Anvuew Karaoke, Becruily Karaoke, Deux, and BandIt Plus DNR. Their fixed Gateway profiles are respectively `dialogue-vocal`, `karaoke-anvuew`, `karaoke-becruily`, `film-dialogue-deux`, and `fx` at `2026-10-28.v2`. Other models, GPU weights, native worker code, and the user interface retain their current paths.

The Stage job records a deterministic `gatewayV2Key` before submission and saves `gatewayV2Task` as soon as Gateway accepts the request. Gateway imports the canonical source or its shared `segment-inputs` window through the scoped hard-link endpoint. Long-film jobs still keep separate execution records and outputs per model. Same-key submit retry retrieves the existing task; restart recovery polls the saved task ID. The consumer verifies the returned profile, roles, SHA-256, size, PCM24 WAV format, source channel count, and 48 kHz frame length before publishing Stage output files. Its local v2 slot pool is independent of the Stage GPU slot; Gateway remains responsible for Provider capacity.

Release order: build both immutable candidates, publish the Gateway API contract and Stage import configuration, complete the Worker-only managed Provider release bound to that exact Gateway digest, grant the five scoped profiles to the existing Stage Client, then promote this Stage CPU candidate. The Stage switch stays off until the preceding dependencies and the exact Client key are verified. A missing profile, denied import, or contract mismatch must stop the candidate without falling back to a different model. Rollback is to disable the switch and restore the prior Stage CPU image; keep existing jobs, Gateway tasks, NAS inputs, and outputs. A task already submitted through v2 must be observed or reconciled under its recorded key; disabling the switch does not authorize a native replay of that task.

The Stage promotion uses `Dockerfile.v2-overlay` over the observed `2005a0a` runtime image and `publish_v2.py` to update only the Compose runtime service. The publisher checks the old image/source, saves the exact Compose and container state, fences new ingress while waiting for idle, and verifies GPU devices, mounts, ports, sibling container IDs, new source and health after replacement. The fixed PR commit must be built from a read-only snapshot and the resulting digest supplied to the publisher. The existing Web container and its `17896` entry remain in place.

Local tests cover canonical inode reuse across models, a lost submit response, a lost status response, independent Stage v2 slots, startup recovery, legacy native boundaries, and film joins. Live Provider/Gateway v2, 90–120 minute film, cross-machine browser testing, network fault injection, and container restart have not yet been accepted. The Stage test URL remains `http://ttd-stage:17896/ui/` after an authorized managed release; the local worktree is not a test link.
